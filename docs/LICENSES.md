## Co-Op (Nucleus Co-op)

Co-Op runs Nucleus Co-op handlers through **PlayOut Co-Op** (`resources\coop\PlayOutCoop.exe` and the files beside
it), a separate program licensed under the **GNU General Public License v3**, built from the Nucleus Co-op engine
(https://github.com/SplitScreen-Me/splitscreenme-nucleus, GPL-3; original author Lucas Assis, Nucleus Co-op by
ZeroFox and the SplitScreen.Me team and contributors). Its complete source code, licence text and list of changes are
at https://github.com/jeremybris/PlayOut-CoOp; the licence text and README are also in `resources\coop`. PlayOut
itself contains none of that code: it starts the separate program and exchanges files and text with it.

Not shipped with PlayOut, and downloaded only on the user's request:

- **Handlers** (community-written scripts, each the work of its author): from the Google Drive folder the user
  chose and the Nucleus Co-op hub (https://hub.splitscreen.me/), kept unmodified on the user's PC.
- **Nucleus Co-op's tools** (the official release from GitHub, the first time Co-Op is used): Nucleus's hook DLLs
  (GPL-3), ProtoInput (MIT, © 2021 Ilyaki), EasyHook (MIT), the Goldberg Steam emulator (LGPL-3), x360ce (LGPL-3),
  SDL2 (zlib) and third-party utilities under their own terms (XInput Plus, Steamless, SmartSteamEmu, ForceBindIP and
  others listed in the release's `utils\Credits.txt`). Some handlers use tools that remove DRM or bypass anti-cheat;
  PlayOut asks before using them for a game.

## PeerParty

LAN play (the game page's PeerParty square) starts games through **PeerParty**
(https://github.com/MaximumFreak/PeerParty), licensed under the **MIT License**, © 2026 PeerParty contributors. It is
not shipped with PlayOut and PlayOut contains none of its code: `peerparty.exe` is downloaded at run time from the
project's latest GitHub release, the first time the user starts a game with it, and used only after it matches the
release's published SHA-256 checksum (and GitHub's own digest of the file). The licences of the software built into
it are listed in the release's `THIRD-PARTY-NOTICES.md`
(https://github.com/MaximumFreak/PeerParty/releases/latest). PlayOut runs it unmodified, in its portable mode, with
its settings and data in PlayOut's data folder (`%APPDATA%\PlayOut\PeerParty`).

## Emulators

The emulators PlayOut sets up are separate programs under their own licences; PlayOut contains none of their code and
downloads them on first-time setup from their official releases (docs/emulator-setup.md), except **RPCS3**
(https://github.com/RPCS3/rpcs3, GPL-2.0): it comes from the user's own preconfigured copy in their Google Drive
folder, not from RPCS3's release, and is kept unmodified apart from its folder settings. RPCS3's source code and
licence are at https://github.com/RPCS3/rpcs3. The PS3 firmware in that copy is the user's own.

## Streaming (Sunshine and Moonlight)

Streaming between two PlayOut PCs uses two separate open-source programs, each licensed under the **GNU General Public
License v3**. Neither is shipped with PlayOut or contains PlayOut code, and PlayOut contains none of theirs: PlayOut
downloads the official portable release from GitHub the first time it is needed (checked against a pinned SHA-256),
keeps it unmodified in `%APPDATA%\PlayOut\streaming\`, and runs it as a separate program through its command line and
local web API.

- **Sunshine** (the host side; https://github.com/LizardByte/Sunshine, GPL-3, © LizardByte and contributors): the
  portable "lite" Windows build. Source code and licence: https://github.com/LizardByte/Sunshine.
- **Moonlight** (the client side; https://github.com/moonlight-stream/moonlight-qt, GPL-3, © the Moonlight
  contributors): the portable Windows build. Source code and licence: https://github.com/moonlight-stream/moonlight-qt.

Controllers on a streaming host use the **ViGEmBus** driver (BSD-3-Clause, https://github.com/nefarius/ViGEmBus),
which the user installs separately; PlayOut only checks whether it is there.

## Memory cleanup (inspiration only)

"Free up memory while PlayOut is running" (Settings › System) was inspired by four open-source Windows tools that
show which temporary techniques exist, and by the warnings in their own source and documentation about when not to
use them:

- **Quiesce** (https://github.com/SibtainOcn/Quiesce, GPL-3.0-or-later, Go).
- **Deltempo** (https://github.com/Beso1227/Deltempo, MIT, Copyright (c) 2026 Deltempo Contributors, C#; its memory
  engine is ported from WinMemoryCleaner).
- **optimizerDuck** (https://github.com/itsfatduck/optimizerDuck, GPL-3.0, Copyright (C) 2025–2026 fatDuck, C#).
- **windows-optimizer-script** (https://github.com/PriyomSaha/windows-optimizer-script, MIT, Copyright (c) 2025 Priyom
  Saha, batch).

PlayOut contains none of their code and none of it was translated: the feature is written from scratch against the
Windows API (`K32EmptyWorkingSet`, `NtSetSystemInformation` with the memory list and memory combining classes,
`AdjustTokenPrivileges`) in `src/main/performance/memory/` and `src/main/performance/helper/csharp.ts`. None of these
tools is shipped with, downloaded by or run by PlayOut. PlayOut also leaves out everything they do that lasts beyond
the moment: it stops or disables no service, removes no app, ends no process and never touches Windows Update,
Microsoft Defender, the firewall, the pagefile or the registry for this.

## PS5 package unpacking (PS5PKGTool)

Settings › Convert › PlayStation 5 › PKG → Game Folder runs **PlayOutPs5Pkg** (`resources\ps5pkg\PlayOutPs5Pkg.exe`), a
separate program, not part of PlayOut's own code: it is licensed under the **GPL-3.0** because it is built on
**PS5PKGTool** by pearlxcore (https://github.com/pearlxcore/PS5PKGTool, GPL-3.0; its `PS5PKGTool.Core` and
`PS5PKGTool.Ffpfsc` projects, and `PS5PKGTool.Ufs2`, which is based on UFS2Tool by SvenGDK under the BSD-2-Clause
licence, all at the commit pinned in `ps5pkg-helper/build.mjs`) and its package engine **ProsperoPkgTool** by pearlxcore
(https://github.com/pearlxcore/ProsperoPkgTool, MIT), built from source without its embedded package-building files
(`Keys\*.bin`, `Resources\right.sprx`). The exe also holds the NuGet libraries PS5PKGTool.Core uses (BCnEncoder.Net,
SixLabors.ImageSharp, CommunityToolkit.HighPerformance, Oodle.NET, a wrapper only: the Oodle DLL itself is not
included) and the self-contained .NET runtime. Its complete source (with the build script) is published at
https://github.com/jeremybris/PlayOut-PS5PKG, and `resources\ps5pkg` carries its `LICENSE` and
`LICENSES-THIRD-PARTY.txt` (every licence and notice text of what is inside the exe). PlayOut only starts it and reads
its output (one JSON line per event). None of the proprietary files PS5PKGTool's own app carries (the Oodle
`oo2core_9_win64.dll`, `libScePubTools.dll`, LibProsperoPkg) is built into or shipped with it; it unpacks fake packages
only, with no Sony keys.

## PS4 package keys

`src/main/convert/ps4-keys.ts` holds the publicly known keys that open fake PS4 packages (fPKG), the same values the

(https://github.com/shadps4-emu/shadPS4) publish. No Sony retail keys and no Sony or Oodle files are included.
